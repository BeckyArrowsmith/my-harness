Call the Skill tool twice, for "grilling" and "domain-modeling".

As decisions settle during grilling, write them into project docs immediately. Don't wait until the grilling is finished. Each time a round of grilling resolves a question (a name, a boundary, a behaviour, a constraint), capture it in the appropriate doc right then: SPEC.md for design decisions, GLOSSARY.md for domain terms, an ADR for architectural choices. The grilling and the docs happen together, not in sequence.
